## 1. 一句话定义

一个封闭源码、限定 10 人以内使用的中文 AI 小说写作 Web 系统，服务于玄幻升级题材的**长篇连续创作**：作者在 10—30 章的规模内，能够得到"设定不崩、人物不傻、战力不乱、伏笔能收"的可用正文。

## 2. 产品目标

### 2.1 业务目标

| 编号 | 目标 | 衡量方式（第一版口径） |
| --- | --- | --- |
| G1 | 验证 AI 能否支撑 10—30 章连续创作而不崩坏 | 存在至少 1 部作品连续完成 ≥10 章，且通过 `04-acceptance-tests.md` 全部一致性用例 |
| G2 | 验证"结构化设定 + 检索 + 一致性检查"闭环优于"一次性生成" | 同一作品在引入一致性检查后，人工返工工时下降（作者主观打分 + 返工轮次记录） |
| G3 | 验证封闭小团队形态的运营成本可接受 | 单部 30 章作品的模型调用成本有明确记录（见 `03-data-model.md` 的 `llm_call_log`） |
| G4 | 建立可持续演进的封闭源码基座 | 后续新增题材不修改通用核心实体，只增加规则包与检查器插件 |

### 2.2 非目标（第一版明确不追求）

- 不追求百万字全自动生成。
- 不追求单章文笔达到人类作者水准；第一版追求"结构不崩 + 可用初稿 + 人工可控"。
- 不追求通用型写作工具（不支持诗歌、剧本、非虚构、英文写作）。
- 不追求成为 SaaS 产品（无公开注册、无自助开通、无推广）。
- 不追求模型自研（不训练、不微调、不做模型评测平台）。

## 3. 目标用户

第一版只有两类角色，且角色由管理员在系统内直接赋予，**不存在第三方自助获取账号的路径**。

### 3.1 管理员（1 人）

通常是产品负责人本人。职责：

- 创建 / 停用 / 重置作者账号。
- 配置系统级参数：模型供应商（单一默认模型）、并发上限、单次生成字数上限、每日 Token 预算上限、单任务 Token 硬上限、上下文召回上限。
- 查看全部任务的执行状态、Token 用量与成本、错误摘要等**运维元数据**。
- 执行备份、恢复演练。
- 配置规则包（第一版内置唯一一个玄幻规则包）。

**隐私边界（硬性）**：管理员**默认不能查看作者正文内容**。管理员可见的仅限任务、成本、错误、账号、配置等运维元数据。若确因排障需要查看正文，必须走**临时授权 + 审计**（见 §7.1）。管理员也不参与作品正文创作，不提供直接编辑作者正文的入口。

**临时查看的批准人（v1.2 明确）**：正文临时查看授权**默认由作品作者本人批准**（管理员发起请求 → 作者批准 → 授权生效）。若采取"管理员自批"，则必须由项目负责人明确记录为决策，且不能宣称"管理员无法查看正文"。此点属负责人决策项，见 `06` Q13。

### 3.2 作者（≤9 人）

内部签约 / 邀请制的少量作者。职责：

- 创建并维护自己的作品。
- 维护设定（世界观、人物、境界体系、势力、物品、资源）。
- 使用流水线生成卷纲、阶段目标、章节细纲、场景节拍、正文。
- 人工编辑正文、保存版本、执行局部重写。
- 运行一致性检查并按报告修订。
- 确认或拒绝系统提取的事实（见 `03` §4 事实闭环）。
- 导出作品。

### 3.3 用户规模与硬边界

- 账号总数上限：**10**，**包含停用账号**（停用不释放名额）。新建账号使用**事务锁**防止并发突破上限（见 `03` §5.2）。
- 单作者并发生成任务数上限：**2**（超出排队）。管理员可下调不可上调超过 2（防止成本失控）。
- 单作品章节数：**不设硬上限**，但受配额与存储约束；第一版验证目标是 10—30 章。
- 单章字数：生成目标 **2500—4000 个中文字**（口径见 §6.1）。
- 单作品世界设定条目（人物 / 势力 / 物品 / 地点 / 功法 / 资源 / 境界层级）总数：设计上限 **2000 条**，单条字段长度上限 4000 字符。

### 3.4 不做的用户形态

明确排除：公开注册、邀请码自助兑换、临时访客、只读分享链接、企业 SSO、第三方 OAuth 登录、API 开放给外部。

## 4. 使用场景

### 4.1 主场景：作者完成一部玄幻长篇的前 10 章

**前置**：管理员已创建作者账号并告知初始密码；作者已登录。

1. 作者进入"我的作品"，新建作品《寒山问道》，选择题材"玄幻升级"（第一版唯一可选题材）。
2. 填写作品方向（题材参数：子类型、金手指、语气风格等，**由规则包驱动**，见 `03` §3.2）、目标字数、章节节奏。
3. 填世界：大陆结构、主要势力、灵石经济、势力等级。
4. 填人物：主角、配角、反派；每个角色含境界起点、性格、目标、秘密。
5. 定义境界体系：炼气→筑基→金丹→元婴→化神，每层含小境界、突破条件描述、寿命。
6. 点击"生成卷纲"，系统产出第一卷的分卷目标与章段区间；作者人工调整后确认。
7. 系统据卷纲生成"十章阶段目标"，作者确认。
8. 作者逐章点击"生成本章细纲"→"生成场景节拍"→"生成正文草稿"。
9. 草稿进入**候选区**，作者预览后"采纳"（成为正式版本）或"放弃"。
10. 作者人工编辑正文，保存为新版本（修改前版本保留）。
11. 点击"玄幻一致性检查"，得到分级问题清单，每条含原文证据与建议修改位置。
12. 作者对某段不满意，执行"局部重写"，选择保留范围，重写后再次检查。
13. 章节定稿后，系统提取事实，作者**接受或拒绝**每条事实，接受后回写人物/资源/设定状态。
14. 第 10 章完成后，执行"导出作品"，得到合并稿与设定附录。

### 4.2 次场景：修一条被打断的生成任务

- 生成过程中 Worker 崩溃 / 模型接口 502 / 用户关闭浏览器。
- 预期：任务状态在恢复后可见（失败或待重试），**已保存的旧章节正文不受任何影响**；作者可手动重试，重试不会产生第二份正式记录。

### 4.3 次场景：管理员排查成本异常

- 管理员在"任务与用量视图"看到某作者 24 小时内 Token 用量异常（因重复点按或上下文召回过大）。
- 处理：下调该作者的并发上限、调整单章召回条数上限、必要时停用账号。
- 注：此过程**不涉及查看正文**。

### 4.4 明确排除的场景

- 多人同时编辑同一作品（第一版无协作）。
- 作者甲浏览作者乙的作品（服务端拒绝，不是前端隐藏）。
- 生成 100 章以上的长篇（超出验证规模）。
- 一键"自动写完整本"（第一版无此功能）。
- 管理员直接翻阅作者正文（默认禁止，见 §7.1）。

## 5. 产品价值

| 价值点 | 具体表现 | 与"直接用通用 AI 对话写小说"的差异 |
| --- | --- | --- |
| 连续性 | 境界、战力、资源、物品、认知、时间线、伏笔七类硬检查 | 通用对话无状态，写到第 8 章必然崩 |
| 可追溯 | 每次生成可回看"用了哪些设定、哪些历史章节、哪些上下文条目" | 通用对话无法回答"为什么这么写" |
| 可恢复 | 重写保留旧版本，一键回滚 | 通用对话改写即覆盖 |
| 可控 | 局部重写，保留未选中的段落 | 通用对话只能整段重来 |
| 私有 | 数据不出自建 VPS，账号由管理员发放，管理员默认不看正文 | 通用产品无法保证内容保密 |

## 6. 范围边界（第一版）

### 6.1 明确的数据边界（不做"以后可扩展"的空话）

| 边界项 | 第一版取值 | 超出时的行为 |
| --- | --- | --- |
| 账号总数 | ≤ 10（**含停用**） | 管理员新建账号接口返回错误，界面不提供绕过入口；事务锁防并发 |
| 角色种类 | 2（admin / author） | 无第三种角色入口 |
| 题材数 | 1（玄幻升级规则包 `xuanhuan`） | 作品创建页只有 1 个题材选项 |
| 单章字数 | 目标 2500—4000 中文字 | 生成结果超出区间时给 warning 提示，不阻断；作者可重生成 |
| 单章最少字数 | 低于 1200 字视为生成失败，不写库 | 任务标记 failed，保留错误信息 |
| 单作品章节数 | 验证目标 10—30；不设硬上限 | 无 |
| 世界设定条目数/作品 | 2000 | 超出时该实体保存失败并提示 |
| 检索范围 | **严格限于单个作品内** | 不提供跨作品检索入口 |
| 导出格式 | Markdown(.md)、纯文本(.txt) 为 P0；Word(.docx) 为 P1 | 不提供 PDF / EPUB / 网页发布 |
| 并发生成 | 每作者 ≤2 | 超出排队，不丢弃 |
| 模型供应商 | **单一默认模型**（OpenAI 兼容协议，预留多 base_url 配置，第一版只启用一个默认模型） | 非 OpenAI 兼容协议需自研适配器，不在第一版 |
| API Key | **仅环境变量 / Docker secret 注入，不入库、不进管理页面** | 管理页面只显示"已配置/未配置"与"测试连接"，不提供输入/保存 Key 入口 |
| Token 预算 | 每日预算上限 + 单任务 Token 硬上限（管理员可配） | 超出硬上限立即拒绝/中止任务，不静默继续 |

### 6.2 字数口径定义（避免验收歧义）

中文字数 = 章节正文中 **CJK 统一表意文字（U+4E00–U+9FFF）+ 扩展 A（U+3400–U+4DBF）+ 兼容表意文字（U+F900–U+FAFF）** 的字符数，**不含**标点、空白、Markdown 语法标记、章节标题。若后续发现口径不一致，以本节为准并同步修订 `04-acceptance-tests.md`。

### 6.3 题材解耦的硬性约束（写入代码评审 checklist）

以下任一情况出现，视为违反架构约束，必须打回：
1. 通用核心表中出现 `realm` / `cultivation` / `sect` / `spiritual_stone` / `sub_genre` / `golden_finger` / `tone_style` 等题材专有列名。
2. 核心页面组件中出现硬编码的"境界""宗门""灵石"标签或字段。
3. 新增题材需要修改通用核心实体（`works` / `chapters` / `chapter_versions` / `chapter_candidates` / `entities` 等）的 DDL。

**修正说明（v1.1）**：v1.0 曾写"新增题材绝不 ALTER 表"，此表述过严，已修正为——新增题材**不修改通用核心实体**，但**允许**规则包使用**独立扩展表**或**增量迁移**（新增表 / 新增可空列，不改已有核心表语义）。题材专有数据仍以通用 `entity` / `entity_attribute` 为主承载，扩展表仅在通用结构无法高效表达时使用。

题材专有参数（如玄幻的子类型、金手指、语气风格）不进入 `works` 表的固定列，而由规则包 `field_schema` 驱动的 `work_settings` 承载（详见 `03-data-model.md` §3.2、§4）。

## 7. 隐私与安全边界

### 7.1 管理员与正文的隔离（v1.1 新增，v1.2 明确批准人）

- **默认禁止**：管理员（即使拥有最高角色）默认**不能查看任何作者的章节正文**。管理员可见对象 = 任务状态、Token 用量、成本、错误摘要、账号、系统配置、审计日志。
- **临时授权查看**：确因排障需要查看某章节正文时，必须：
  1. 管理员发起"正文查看授权"请求，填写事由、范围、时长；
  2. **由作品作者批准**（默认），批准后授权生效；
  3. 授权有时效（默认 1 小时）与范围（限定具体作品/章节）；
  4. 每次查看写入**审计日志**（who/when/what/why）。
- **批准人决策（须负责人拍板，见 `06` Q13）**：
  - 方案 A（默认）：作者批准。
  - 方案 B：管理员自批 —— 若采用，须由项目负责人明确记录，且不得宣称"管理员无法查看正文"。

### 7.2 其他安全边界

- API Key 不入浏览器、不入 Git、不入日志（见 `05` §1.3）。
- 作者数据服务端鉴权，前端隐藏不构成安全边界。

## 8. 第一版成功判定（Exit Criteria）

全部满足才算第一版达成，否则进入"第二版迭代"而非"验收通过"：

1. `04-acceptance-tests.md` 中 P0 级用例 **100% 通过**，P1 级用例 ≥ 90% 通过。
2. 存在至少 1 部作品实际完成 **10 章**，每章均留存：细纲、场景节拍、至少 1 个人工编辑版本、1 次一致性检查报告、事实提取记录。
3. 服务重启后，所有作品、版本、任务状态、设定条目无损（用例 AT-R1 全绿）。
4. 模型调用失败、重复提交、Worker 中断、双 Worker 抢任务四类故障场景下 **没有产生任何半写状态或重复记录**（用例 AT-F1/AT-F2/AT-C2/AT-Q1 全绿）。
5. 所有直接依赖与传递依赖许可证检查通过，无 AGPL/GPL 传染（`05-architecture-and-licenses.md` §6）。
6. 管理员可导出全局 Token 用量与估算成本，并能与模型供应商账单对上（误差 ≤ 10%）；每日预算与单任务 Token 硬上限可生效（AT-CTX-4/AT-CTX-5）。
7. 管理员默认无法查看正文；临时授权查看全程留审计（AT-PRV-1/AT-PRV-2）。
