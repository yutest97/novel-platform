# 04 验收测试（Acceptance Tests）

- 版本：v1.0（方案稿，待技术负责人审查）
- 状态：**未获批准。**

本文定义可执行的验收用例，覆盖：创建作品→导出章节全流程、10 章连续性、七类一致性检查、服务重启/API 失败/重复任务等故障场景。用例编号供阶段验收引用。

---

## 0. 测试环境与前置

- 前置数据：管理员 1 名、作者 2 名（作者 A、作者 B）、一个已配置的 OpenAI 兼容模型供应商（可用**桩/模拟模型**，不要求真实付费 API）。
- 测试数据可重复构建（seed 脚本），测试可重复运行。
- 每个用例含：步骤、预期、失败判据。

---

## 1. 全流程验收（创建作品 → 导出）

### AT-FLOW-1 完整创作闭环

| 步骤 | 预期 |
| --- | --- |
| 管理员创建作者 A | 成功，一次性密码展示 |
| A 首登改密 | 强制改密后进入"我的作品" |
| A 新建玄幻作品《测试·寒山》 | 题材仅 1 项；进入向导 |
| A 完成方向/世界/人物/境界体系/势力/物品 | 最小设定集满足（主角 + 境界 ≥3 层） |
| A 生成卷纲 | 卷纲落库，可查看上下文来源 |
| A 生成十章阶段目标 | 每章 1—3 条目标 |
| A 生成第 1 章细纲 → 节拍 | 节拍字数预算偏差 ≤20% |
| A 生成第 1 章正文 | 2500—4000 字，落草稿区 |
| A 采纳 → 人工编辑 → 保存 | 产生 human 版本，版本号递增 |
| A 一致性检查 | 返回 7 类检查结果（可无问题） |
| A 局部重写 | 未选段落逐字节不变 |
| A 保存新版本 → 导出 | 导出含正文+卷纲+设定附录 |

**失败判据**：任一步骤无法完成，或越权/半写/重复记录等硬性要求被破坏。

## 2. 数据隔离与权限测试

| 编号 | 用例 | 预期 |
| --- | --- | --- |
| AT-SEC-1 | 作者 B 直接请求作者 A 作品/章节/设定的接口 | `403`，不返回任何 A 数据 |
| AT-SEC-2 | 作者 B 通过"猜测 work_id"访问 A 的章节 | `403` 或 `404`（不可区分是否存在） |
| AT-SEC-3 | 作者请求管理员接口（建号/配置/用量） | `403` |
| AT-SEC-4 | 未登录访问任意业务接口 | `401` |
| AT-SEC-5 | 停用作者 A 后，A 的现有会话请求 | 立即 `403`（不等 token 过期） |
| AT-SEC-6 | 前端隐藏他人作品入口（仅验证 UI 不出入口，**不作为安全依赖**） | 服务端仍拦截，UI 隐藏仅体验 |

**失败判据**：任何一条返回他人数据或越权成功。

## 3. 版本与可恢复性测试

| 编号 | 用例 | 预期 |
| --- | --- | --- |
| AT-VER-1 | 生成正文后采纳 → 再生成一稿 | 版本号 1、2 并存，1 内容不变 |
| AT-VER-2 | 人工编辑保存 | 产生 `human` 版本，父版本可追溯 |
| AT-VER-3 | 局部重写未选段落 | 未选段落与重写前逐字节一致 |
| AT-VER-4 | 恢复历史版本 | 恢复写为新版本，历史版本数量只增不减 |
| AT-VER-5 | 任意两版本 diff | 差异正确高亮，无遗漏 |
| AT-VER-6 | 生成失败（模拟模型报错） | 无新正式版本产生，旧版本完好 |

**失败判据**：任何旧版本被覆盖或丢失。

## 4. 七类一致性检查测试

> 每类均需**至少 1 条可真实触发的规则**。测试用"注入矛盾数据"方式构造，断言检查器能命中。

| 编号 | 类别 | 构造的矛盾 | 预期问题证据 |
| --- | --- | --- | --- |
| AT-CHK-1 | 境界 | 第 5 章人物从"筑基"变"金丹"，但境界体系里筑基→金丹需突破条件且时间线未满足 | 命中"境界跳跃"问题，含原文引用与建议位置 |
| AT-CHK-2 | 战力 | 金丹期人物被炼气期反派轻易击败，且无合理铺垫 | 命中"战力倒挂"问题 |
| AT-CHK-3 | 资源 | 第 3 章灵石余额 100，第 6 章花费 500 无补充 | 命中"资源透支"问题 |
| AT-CHK-4 | 物品 | 法宝持有人为甲，第 7 章乙使用且无转手事件 | 命中"物品归属矛盾"问题 |
| AT-CHK-5 | 认知 | 人物甲"知道"了某秘密，但该秘密 knowledge_scope 标记为甲不可知 | 命中"认知越界"问题 |
| AT-CHK-6 | 时间线 | 事件 B 发生时间早于其因果前提事件 A | 命中"时序矛盾"问题 |
| AT-CHK-7 | 伏笔 | 计划回收章已过，伏笔状态仍"未回收" | 命中"伏笔未回收"提示 |

**失败判据**：任一类别无法触发规则，或命中问题缺少原文证据/建议位置。

## 5. 10 章连续性测试

### AT-CONT-1 连续生成 10 章

- 步骤：按 AT-FLOW-1 闭环连续完成第 1—10 章（每章至少 1 个 human 版本 + 1 次检查）。
- 预期：10 章全部 `finalized`；卷纲/阶段目标/细纲/节拍/正文/版本/检查报告链完整。
- 额外断言：**第 N 章生成时的上下文来源可回看**（AT-CTX-1），且引用的是当时的历史章节与设定版本。

### AT-CONT-2 跨章实体状态一致

- 步骤：检查 10 章中某人物境界、某资源余额、某物品持有人，按章节顺序回放事件流水。
- 预期：流水回放结果与各章正文陈述一致，无跳变。

### AT-CONT-3 设定变更不污染已生成章节

- 步骤：在第 6 章定稿后修改境界体系（如新增一层），再回看第 6 章。
- 预期：第 6 章历史版本内容不变；其"当时设定版本"快照仍可回放。

## 6. 故障与持久化测试

| 编号 | 用例 | 预期 |
| --- | --- | --- |
| AT-R1 | 服务重启 | 重启后作品/章节/版本/设定/任务状态全量无损 |
| AT-R2 | 生成中 Worker 崩溃 | 任务状态可恢复（failed 或可重试），无半写章节 |
| AT-F1 | 模型 API 超时/502 | 任务 `failed`，错误记录可查，旧章节不受影响 |
| AT-F2 | 模型返回 <1200 字 | 不落库，任务 `failed`，可重试 |
| AT-C2 | 重复点击"生成" | 仅 1 个 task，仅 0/1 个正式版本（幂等） |
| AT-C3 | 正文写入与状态更新的原子性 | 模拟写入中途失败 → 无"正文已写、状态未更新"的半写态 |
| AT-C4 | 并发编辑同章节 | 一方得 `409`，另一方成功，版本号不冲突 |

## 8. 验收通过口径（呼应 `00` §7）

- P0 用例 100% 通过，P1 ≥90%。
- 存在 1 部作品完成 10 章（AT-CONT-1）。
- AT-R1 / AT-F1 / AT-F2 / AT-C2 / AT-C3 全绿（故障无半写）。
- AT-CHK-1~7 全绿（7 类检查均可触发且证据完整）。
- 许可证检查通过（见 `05` §6）。

> 说明：上述用例由实现方在阶段二落地为自动化测试（优先集成测试 + 桩模型）；本轮仅定义用例，**不视为已通过**。
