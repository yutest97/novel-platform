# N1：AI 小说创建向导方案

- 状态：待实施
- 目标基线：A2 CI #25 已验收（`07cb346`）
- 执行方：Trae
- 产品目标：用户从“新小说”入口开始，通过分步骤问答形成核心创意、世界观、人物、
  全书主线、分卷和章节大纲，确认后进入逐章写作。

## 1. 产品原则

```text
创作向导（工作流） → 专用 Agent / Skill → 结构化候选 → 作者确认 → 正文生成
```

- 向导步骤、状态和保存由代码控制；
- Agent 只生成当前步骤的结构化建议，不决定下一步；
- 所有 AI 结果先成为可编辑候选，作者确认后才写入故事圣经；
- 全书大纲未确认前不得生成正文；
- 已确认的大纲可继续修改，但必须留下版本或明确的新一轮修订；
- 不用 Agent 自由对话替代固定流程。

## 2. 用户体验

用户点击“写新小说”后，进入单页分步向导：

1. **基础信息**
   - 书名
   - 题材
   - 男频 / 女频 / 通用
   - 目标读者
   - 预计总字数
   - 单章目标字数
   - 叙事视角
   - 整体基调
   - 节奏

2. **核心创意**
   - 一句话卖点
   - 主角初始处境
   - 核心冲突
   - 金手指 / 核心优势
   - 主要悬念
   - 期望结局方向

3. **世界观**
   - 世界背景
   - 力量体系
   - 势力分布
   - 地域结构
   - 社会规则
   - 世界限制与禁忌

4. **人物**
   - 主角
   - 反派
   - 核心配角
   - 人物关系
   - 人物目标
   - 人物秘密
   - 人物成长弧

5. **全书主线**
   - 开局事件
   - 第一次升级
   - 中期转折
   - 最大危机
   - 高潮
   - 结局
   - 主要伏笔

6. **分卷**
   - 卷名
   - 本卷目标
   - 主要冲突
   - 关键转折
   - 本卷高潮

7. **章节大纲**
   - 章节号 / 标题
   - 章节目标
   - 场景
   - 冲突
   - 结果
   - 出场人物
   - 伏笔与回收

8. **总览确认**
   - 全部内容可编辑
   - 显示缺失项和内部冲突
   - 作者确认后才创建正式作品与章节计划

## 3. 数据分层

### 3.1 草稿蓝图

`novel_blueprints`：向导中的可编辑草稿，不代表正式作品。

- 归属作者；
- 保存当前步骤、全部答案、版本号和状态；
- 不为每个未完成向导创建正式 `works` 行；
- 支持刷新恢复、乐观并发和删除草稿。

### 3.2 确认后的故事圣经

确认事务将蓝图写入现有正式模型：

- `works`：书名、简介、目标章节数、单章目标字数、题材；
- `work_settings`：世界观与其他规则包字段；
- `entities` / `entity_attributes` / `entity_versions`：人物、势力、境界、物品等；
- 新增大纲表保存全书、分卷、章节计划；
- `chapters` 仅在作者确认大纲后按计划创建，初始状态 `planned`；
- 蓝图状态改为 confirmed，并记录生成的 workId；
- 全部成功或全部回滚。

### 3.3 大纲

建议新增：

```text
novel_outlines
  id, work_id, kind(book|volume|chapter),
  parent_id, order_index, title, summary, payload(jsonb),
  status(candidate|confirmed), version_no, created_by, created_at
```

不在本方案第一阶段直接冻结具体结构；N1-B 开卡时根据向导实际字段再收敛。

## 4. Agent / Skill 分工

每个步骤可有独立的内部能力模块：

| 能力 | 输入 | 输出 |
| --- | --- | --- |
| Idea Agent | 基础选项、用户补充 | 核心创意候选 |
| Worldbuilding Agent | 题材、核心创意 | 世界观候选 |
| Character Agent | 创意、世界观 | 人物与关系候选 |
| Outline Agent | 已确认设定 | 全书主线、分卷候选 |
| Chapter Outline Agent | 全书 / 分卷 | 章节大纲候选 |
| Writer Agent | 已确认章节大纲 | 正文候选 |
| Reviewer Agent | 正文 + 已确认故事圣经 | 问题候选 |

“Skill”在软件内部是版本化提示词 / 规则模块，不是 Codex 外部 Skill。

## 5. 实施阶段

### N1-A：向导、蓝图与确认落库

- 新增“写新小说”入口；
- 新增蓝图草稿表与服务；
- 8 步向导 UI；
- 固定选项 + 自由输入；
- 草稿刷新恢复、步骤导航、校验；
- 最终确认创建正式作品、基础设定、人物和首批章节计划；
- 本阶段不调用 LLM。

### N1-B：AI 辅助生成

- 每个步骤的专用 Agent 契约与 Mock；
- “根据当前答案生成候选”；
- 候选可编辑、重新生成、确认；
- 失败不覆盖已确认内容；
- 世界观、人物、全书/分卷/章节大纲。

### N1-C：大纲驱动章节写作

- Writer 输入优先读取已确认章节大纲；
- 章节大纲转成现有 `Planner` 合同；
- 禁止绕过未确认大纲直接写作；
- Reviewer 检查正文对大纲的遵循；
- 定稿后摘要和事实继续维护故事连续性。

## 6. 第一阶段验收

N1-A 完成后，用户应能：

1. 在作品空间点击“写新小说”；
2. 通过 8 步表单完成基础信息、创意、世界观、人物、主线、分卷和章节大纲；
3. 中途关闭页面后恢复草稿；
4. 在确认前修改任意步骤；
5. 确认后得到正式作品、人物设定和首批章节计划；
6. 在章节列表看到按大纲创建的第 1 章；
7. Agent/LLM 未配置时整个向导仍可手动完成。

N1-B 才加入“一键 AI 生成 / 重新生成”能力；N1-C 才把大纲用于正文生成。

## 7. 不做

- 开放式 Agent 聊天；
- 自动无限生成整本小说；
- 未确认大纲直接写作；
- 每次保存自动覆盖故事圣经；
- 将 Codex Skill 作为应用运行时；
- RAG / embedding / 图数据库；
- 多作者协作。
